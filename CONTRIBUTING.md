# Contributing to AUVI

First off, thank you for considering contributing to AUVI! It's people like you that make the open-source community such an amazing place to learn, inspire, and create.

## How Can I Contribute?

### Reporting Bugs
If you find a bug, please use the GitHub Issue Tracker and select the **Bug Report** template. Ensure you provide:
- Steps to reproduce the behavior.
- Expected vs. actual behavior.
- Screenshots and logs if applicable.

### Suggesting Enhancements
Have an idea for a new feature? Great! Use the **Feature Request** template in the Issue Tracker. Describe the feature in detail and explain why it would be beneficial to the community.

### Pull Requests
We gladly accept Pull Requests (PRs). When contributing code:
1. **Fork** the repository and create your branch from `main`.
2. Name your branch descriptively (e.g., `feat/add-new-ai-model` or `fix/subtitle-sync`).
3. If you've added code that should be tested, add tests!
4. Ensure the test suite passes locally.
5. Make sure your code lints (if applicable).
6. Use the provided Pull Request template when submitting.

## Development Setup
Please refer to the `Quick Start Guide` in the [README.md](README.md) for instructions on how to set up the project locally.

- **Backend (Python):** Make sure to run inside a virtual environment. We use `pip` for dependencies.
- **Frontend (React/Vite):** We use `npm` for managing Node dependencies. 

## Styleguides
- **Python**: We follow standard PEP-8 conventions. Consider running an auto-formatter before committing.
- **React**: Ensure components are functional and utilize hooks appropriately. Keep Tailwind classes organized.
- **Commit Messages**: Try to use semantic commit messages (e.g., `feat: added option to choose resolution`, `fix: corrected typo in prompt`).

Thank you for your time and contribution!
